# 予算管理SaaS 機能設計書

- 文書バージョン：1.4
- 更新日：2026-10-26
- ステータス：基本設計（未確定事項は末尾に記載）
- 対象：複数企業が利用するマルチテナント型クラウド予算管理サービス
- 技術前提：Java 17 / Spring Boot / Thymeleaf / Spring Security / MyBatis / PostgreSQL

## 1. 目的と基本方針

本サービスは、企業が自ら利用登録し、部門・プロジェクト単位で予算を計画・申請・承認・実績管理できるSaaSである。会計ソフトとはAPI連携し、会計実績の取得・照合・集計を支援する。

### 1.1 確定要件

1. **企業セルフサービス登録**：企業担当者がWeb画面からテナントを作成できる。
2. **部門・プロジェクト単位の予算管理**：部門別集計に加え、プロジェクト別の予算・実績・残額を管理する。
3. **会計ソフトAPI連携**：CSVのみを前提とせず、会計ソフトごとのAPIアダプターを介して接続する。

### 1.2 設計原則

- テナント間のデータ分離をすべての画面・API・ジョブ・ファイル処理で徹底する。
- 権限はロールとデータ範囲（全社、部門、担当プロジェクト等）の両方で判定する。
- 予算変更は申請・承認ワークフローを通し、承認完了前の変更を集計に反映しない。
- 会計実績は外部システムの識別子と同期履歴を保持し、再同期による二重取込を防ぐ。
- 金額集計の定義を一元化し、ダッシュボード・一覧・帳票で同じ結果を返す。

## 2. 対象ユーザーとロール

| ロール | 主な権限 |
|---|---|
| SaaS運用管理者 | SaaS全体の運用・障害調査。業務データの閲覧は必要最小限とし、操作を監査記録する |
| テナント管理者 | 自社設定、ユーザー招待、ロール付与、会計連携設定、マスタ管理 |
| 経営層 | 全社ダッシュボード、全社予算・レポートの閲覧、規程で定めた最終承認 |
| 財務管理者 | 予算編成、勘定科目・会計期間、実績照合、予算・実績レポート |
| 部門責任者 | 所管部門の予算・申請・承認、部門配下のプロジェクト管理 |
| プロジェクト責任者 | 担当プロジェクトの予算・申請・実績閲覧。付与された範囲で承認 |
| 承認者 | 承認経路に割り当てられた申請の承認・差戻し・却下 |
| 申請者 | 権限範囲内の予算・支出申請の作成、提出、状況確認 |
| 監査担当者 | 許可された範囲の監査ログ・変更履歴・レポートの参照 |

ロールだけで許可を決めず、`tenant_id`、ユーザーに割り当てた部門・プロジェクト範囲、レコード状態も確認する。申請者本人による自己承認は禁止する。現行実装では部門・プロジェクト責任者に範囲を割り当て、対象外データへのアクセスを制限する。

## 4. 企業セルフサービス登録

### 4.1 登録フロー

1. 利用者が企業名、企業識別用情報、管理者氏名、メールアドレス、パスワード等を入力する。
2. 利用規約・プライバシー関連の必要な同意を取得する。
3. メール認証用の期限付き・一回限りトークンを発行する。
4. メール認証が完了したら、テナントと初期管理者を作成または有効化する。
5. 初回ログイン後に初期セットアップ画面へ遷移する。
6. 企業名、会計年度開始月、必要に応じて初期部門を設定する。現行はJPY・Asia/Tokyoを使用する。
7. 必要に応じて会計ソフト連携を設定し、接続テストを行う。
8. セットアップ完了後、ダッシュボードを表示する。

### 4.2 登録時の要件

- メールアドレスは正規化して重複を検出する。
- 企業名だけで重複判定しない。法人識別番号等を使う場合は国・地域と利用方針を別途確定する。
- 登録リクエスト、認証メール再送、ログインにレート制限を設ける。
- メール認証前のテナントは利用制限状態とし、認証期限切れの処理を設ける。
- 初期管理者にはテナント管理者権限を付与する。初期管理者の退職・紛失に備えた復旧手順を設ける。
- テナント作成と初期管理者作成は、途中失敗で不整合にならないトランザクション設計とする。
- 料金プラン・試用期間・利用上限は拡張可能な設計とし、具体的な課金要件は別途確定する。

## 5. 部門・プロジェクト・予算の関係

### 5.1 基本モデル

- 1テナントに複数の部門を登録できる。
- 1部門に複数のプロジェクトを関連付けられる。
- プロジェクトには責任者、開始日、終了日、状態を設定できる。
- 予算明細は会計年度、部門、プロジェクト（任意または規程上必須）、勘定科目、期間、金額を持つ。
- プロジェクトに属さない部門共通費を許容するかはテナント設定とする（初期値・運用ルールは要確定）。
- 部門予算とプロジェクト予算の両方を集計表示しても、同じ金額を全社合計に二重加算しない。

### 5.2 プロジェクトの状態

- `draft`：準備中
- `active`：進行中
- `on_hold`：保留
- `completed`：完了
- `archived`：アーカイブ

終了・アーカイブ済みプロジェクトも過去実績の参照は可能とする。新規申請・新規予算配賦を許可するかは状態とテナント設定で制御する。

### 5.3 集計ディメンション

最低限、以下を集計・絞込に利用する。

- 会計年度・期間
- 部門
- プロジェクト
- 勘定科目
- 予算種別
- 申請・承認状態
- 実績計上日、会計ソフト、同期状態

## 6. 予算管理

### 6.1 予算ライフサイクル

`draft → submitted → under_review → approved / returned / rejected`

- `draft`：編集可能
- `submitted`：提出済み
- `under_review`：承認中
- `returned`：差戻し後、申請者が修正可能
- `approved`：承認完了
- `rejected`：却下。再提出を許す場合は新しい版または再申請として扱う

承認済み予算の直接上書きは禁止する。改訂は変更イベントとして記録し、承認完了後にのみ有効額へ反映する。

### 6.2 予算項目

- 会計年度
- 部門
- プロジェクト（任意または設定により必須）
- 勘定科目
- 予算期間（月次・四半期・年次など。採用粒度は要確定）
- 当初予算額
- 承認済み増減額
- 予算責任者
- 状態、版番号、作成者、承認者、更新日時

### 6.3 金額定義

- **現在予算** = 当初予算 + 承認済み予算変更イベントの合計
- **累計実績** = 対象期間内の確定済み実績金額の合計
- **残額** = 現在予算 − 累計実績
- **執行率** = 累計実績 ÷ 現在予算 × 100
- 現在予算がゼロの場合、執行率はゼロ除算せず `—` と表示する。
- 予約額を採用する場合、**利用可能額** = 現在予算 − 累計実績 − 有効予約額。実績へ計上された時点で同じ支出の予約額を解放し、二重控除を防ぐ。

### 6.4 予算変更

- 増額・減額、理由、対象予算、申請者、添付、承認経路を記録する。
- 承認前の変更は現在予算に反映しない。
- 承認完了時に変更イベントを一度だけ確定する。
- 同時承認・再送信による二重反映を防ぐため、排他制御と冪等性を用いる。
- 変更履歴は削除せず、取消・訂正イベントを追加して追跡可能にする。

## 7. 支出申請・承認

### 7.1 支出申請項目

- 申請番号、件名、目的、申請者
- 部門、プロジェクト、勘定科目
- 申請金額、通貨、希望日
- 対象予算、添付ファイル、コメント
- 状態、承認経路、承認履歴

### 7.2 承認ルール

金額による承認経路の例（本番規程に合わせてテナントごとに設定する）。

| 金額 | 承認経路の例 |
|---|---|
| 10万円未満 | 部門責任者 |
| 10万円以上100万円未満 | 部門責任者 → 財務承認者 |
| 100万円以上 | 部門責任者 → 財務責任者 → 経営承認者 |

この金額帯は初期案であり、確定した企業規程ではない。金額、部門、プロジェクト、勘定科目、例外条件でルールを設定可能にする。

### 7.3 状態遷移

`draft → submitted → pending_approval → approved / returned / rejected / cancelled`

- `returned`：修正して再提出可能
- `rejected`：却下。履歴を保持する
- `cancelled`：承認開始前など、規定された条件で申請者が取消可能
- 承認後の取消・金額変更は別イベントとして処理する
- 申請者本人による自己承認は禁止
- 承認時は対象レコードの状態を再確認し、二重承認を防ぐ

## 8. 経営ダッシュボード・レポート

### 8.1 ダッシュボード指標

- 当初予算、現在予算、累計実績、残額、執行率
- 予算超過・超過見込
- 部門別予算・実績
- プロジェクト別予算・実績
- 勘定科目別の実績
- 承認待ち申請、期限超過申請
- 会計連携の最終同期日時、失敗件数

### 8.2 絞込・表示

会計年度、期間、部門、プロジェクト、勘定科目で絞り込める。権限外の部門・プロジェクトは候補にも結果にも表示しない。全社合計とディメンション別内訳の合計が一致することをテストする。

## 9. 会計ソフトAPI連携

### 9.1 基本方針

会計ソフトごとに異なるAPI仕様を、共通コネクタ・インターフェースの背後に隠蔽する。対象会計ソフトは未確定のため、まずコネクタ基盤と1製品目の実装を分離する。

### 9.2 連携機能

- 接続先の登録・解除
- OAuth 2.0等の認証方式への対応（連携先の仕様に従う）
- アクセストークン・リフレッシュトークン・APIキー等の暗号化保管
- 接続テストと必要スコープの確認
- 同期対象期間・同期頻度の設定
- 勘定科目、部門、プロジェクト、取引先等のコードマッピング
- 実績データの差分取得・ページング
- 手動同期・定期同期
- 同期履歴、件数、最終成功時刻、エラー詳細
- リトライ、レート制限対応、再実行
- 取込データと元システムの識別子を用いた重複防止
- 会計期間締め後の修正・取消・遅延到着データへの対応

### 9.3 同期の原則

- ブラウザーJavaScriptは同期受付APIの呼び出し、実行IDの表示、履歴状態の更新を担当する。会計APIアクセス、テナント検証、認可、同期状態遷移、DB更新はJava側で行う。
- 同期ワーカーとオンライン画面は初期構成で同一PostgreSQLを使う。別DBへ分けず、専用Executorと接続プール・同時実行数の制限で負荷を制御する。
- 会計サービス未選定の間、実同期を成功扱いにするモックは提供しない。先行実装は共通受付・履歴・状態照会とし、接続先固有処理は選定後にコネクタとして追加する。
- 現在は `/accounting` 画面、`POST /api/accounting/connections/{id}/sync`、`GET /api/accounting/sync-runs`、`POST /api/accounting/sync-runs/{id}/retry` と、Javaワーカーの共通基盤を実装済み。コネクタが未登録なら受付しない。コネクタが保存した実績は予実集計にも加算する。
- 予実レポートではJavaScriptで部門選択に応じてプロジェクト選択肢を絞り込む。これは操作補助であり、最終的な部門・プロジェクト権限検証はサーバー側で必ず行う。

- 同期ジョブはテナント単位で実行し、ジョブ引数からテナントを確実に検証する。
- ページング、差分カーソル、同期開始・終了時刻を保存する。
- 一時障害は指数バックオフ等で再試行し、恒久エラーは管理者に通知する。
- 同じ外部取引を再取得しても、外部システム名・接続ID・外部レコードID等の一意キーで二重登録しない。
- データの作成・更新・取消を区別し、元データを追跡できるようにする。
- 認証情報や個人情報をログに出さない。
- API利用上限・規約・データ保持条件を連携先ごとに確認する。
- 初期リリースでは会計ソフトから予算管理SaaSへの実績取得を基本とする。会計ソフトへの仕訳登録・書戻しなどの双方向連携は対象ソフトと要件を確定してから追加する。

### 9.4 エラーと運用

| エラー種別 | 対応 |
|---|---|
| 認証期限切れ・権限不足 | 接続状態を要対応にし、管理者へ通知 |
| レート制限 | `Retry-After` 等を尊重し、バックオフして再試行 |
| 一時的なネットワーク障害 | 回数上限付き自動再試行 |
| 項目マッピング不備 | 該当レコードを隔離し、修正後に再処理 |
| 重複データ | 冪等キーで抑止し、同期ログに記録 |
| API仕様変更 | コネクタ単位で影響を分離し、テスト後にリリース |

## 10. 通知

- 企業登録・メール認証
- ユーザー招待
- 予算提出・承認・差戻し・却下
- 支出申請の承認依頼・結果
- 予算超過・超過見込
- 会計連携失敗、認証期限切れ、長時間未同期
- 期限が近い申請・承認タスク

通知本文に機密情報を過剰に含めず、ログイン後の詳細画面へ誘導する。

## 11. 監査ログ

少なくとも以下を記録する。

- ログイン成功・失敗、メール認証、パスワード・MFA関連イベント
- テナント作成・設定変更
- ユーザー招待、停止、ロール・範囲変更
- 部門・プロジェクト・勘定科目マスタ変更
- 予算作成・変更・提出・承認・差戻し・却下
- 支出申請・承認操作
- 会計連携の接続・解除・認証更新・同期開始・終了・失敗
- データ出力・エクスポート
- SaaS運用者による管理操作

ログは発生日時、テナント、操作者、操作、対象ID、結果、相関ID等を保持し、一般ユーザーが改ざん・削除できない設計とする。機密情報・トークン・パスワードは記録しない。

## 12. 受け入れ基準

1. 企業登録からメール認証、初期管理者ログイン、企業名・会計年度開始月・任意の初期部門設定まで完了できる。勘定科目、複数通貨、複数タイムゾーンは後続対象。
2. 未認証テナントが制限された状態で扱われ、認証期限・再送・重複登録に対処できる。
3. あるテナントの利用者が、他テナントの画面/API/ファイル/ジョブのデータを参照・更新できない。
4. 部門別・プロジェクト別・全社集計が整合し、二重計上しない。
5. 承認前の予算変更は現在予算に反映されず、承認後に一度だけ反映される。
6. 申請者本人が自己承認できない。
7. 会計連携を再実行しても同じ外部取引が二重登録されない。
8. API障害・認証切れ・レート制限・マッピング不備がログに残り、管理者が対応できる。
9. すべての重要操作が監査ログで追跡できる。
10. 権限外の部門・プロジェクト・レポートが表示・エクスポートされない。
